# mary-language

AI가 쓴 한글을 **"그 글 자신의 목소리"로 되돌리는** 한국어 윤문(변환) 스킬.
Claude Code / Claude 용. 새 글을 쓰는 도구가 아니라, **이미 작성된 글**의 AI 티를 걷어내
사람 문체로 바꾼다. 내용·사실·구성은 그대로 두고 문체만.

> A Korean prose humanizer skill — but voice-**preserving**, not voice-**standardizing**.

## 이게 왜 다른가 (범용 휴머나이저와의 차이)

대부분의 "AI 티 제거" 도구는 어떤 글이든 **표준적인 자연스러운 한국어**로 민다.
그러면 개성 있는 저자를 밋밋하게 만들 수 있다. mary-language는 반대다:

- **문서 자신의 목소리를 앵커로 삼는다.** 대상 원고에서 "이건 사람이 썼다" 싶은 문단을
  골라, 나머지를 그 결에 맞춰 되돌린다. 일반 taxonomy가 아니라 *이 글의* 목소리.
- **주제어는 척추다.** 그 글이 반복하는 핵심어·중심 은유는 틱이 아니라 논지다. 범용
  도구가 "반복"으로 오탐하는 것을 보호한다.
- **개인 블록리스트.** `references/phrases.md`는 "내가 싫어하는 AI 표현" 목록. 범용
  표준이 아니라 한 저자의 취향에 맞춘다.
- **바뀌면 안 되는 것은 코드가 대조한다.** 각주·숫자·직접 인용이 하나라도 사라지거나
  달라지면 변환본을 채택하지 않는다. 문체는 모델이 바꾸고, 사실은 스크립트가 지킨다.

책·장편·특정 문체 프로젝트처럼 **지켜야 할 목소리가 있는 글**에 쓴다.

## 구조 (3층, 경량)

```
SKILL.md               변환 절차 7단계 · 목소리 앵커 · 금지 문형 · 루브릭 · 힘 다이얼
references/phrases.md  블록리스트(AI 티 표현) — 섹션 태그로 게이트/참고/설명 구분
scripts/mary_gate.py   결정적 계측 게이트 (SSOT) — 의존성 0, LLM 0콜
tests/test_gate.py     게이트 회귀 테스트 (사람 글 통과 · AI 글 목록 · 유실은 채택 금지)
```

## 설치

```bash
git clone https://github.com/mary-jeon/mary-language ~/.claude/skills/mary-language
```

또는 이 폴더를 `~/.claude/skills/` 아래에 둔다. Claude Code가 스킬을 자동 인식한다.
게이트 스크립트는 Python 3.8 이상이면 되고 설치할 패키지는 없다.

> 같은 말("윤문", "AI 티 빼줘")에 반응하는 다른 윤문 스킬이 함께 설치돼 있으면 어느
> 쪽이 뜰지 정해지지 않는다. 하나만 켜 둔다.

## 사용

Claude에게 자연어로:

> "이 글 윤문해줘" · "AI 티 빼줘" · "작가 말투로 바꿔줘"

변환 후 게이트를 직접 돌려 확인할 수도 있다:

```bash
python scripts/mary_gate.py --before 원본.md --after 변환본.md
```

Windows에서는 `python3`가 아니라 `python`이다(`python3`는 스토어 안내 껍데기라 실행되지
않는다). 한글 콘솔(cp949)에서도 그대로 돈다.

## 게이트 — "이 수치가 SSOT다"

이 스킬의 원죄는 *"측정 안 하고 됐다고 말하는 것"*이었다. 그래서 `mary_gate.py`가 결정적으로
판정한다. 다만 **게이트가 매번 울면 무시된다.** 사람 글의 정상 문장까지 "고칠 목록"에 올리던
v2를 세 층으로 나눴다(v3, 2026-09-02):

| exit | 뜻 | 무엇이 여기 드나 |
|---|---|---|
| **2** | 하드 위반 — 변환본 채택 금지 | **각주 유실 · 숫자 유실 · 직접 인용 변형.** 원본↔변환본을 등장 횟수까지 대조한다. 코드가 완전히 판정하는 축 |
| **1** | 고칠 목록 — 전수 처치 전 완료 선언 금지 | 사용자가 확정한 금지 문형만: 대시(— –), '아니라' 정정 골격, 문두 경성 접속부사(그러나·따라서·또한·그러므로·한편·하지만), 강조어·가짜 강조·메타 선언(`phrases.md`의 `[게이트]` 섹션), 450자+ 문단, 지시어 5개+ 문단, 선언 연쇄(인접 문장이 같은 내용어를 재선언), 영문 용어 유실, 원본에 없던 각주 |
| **0** | 통과 | 아래 참고 정보는 exit에 영향 없음 |
| 3 | 판정 불가 | 입력 파일 문제 |

**참고(판정 무관)로만 표시하는 것:** 삼항 병렬 후보, 문단별 쉼표 지도, 한 문장 쉼표 3개+,
미들닷, 블록리스트의 나머지 섹션, 나/내 밀도. 내용과 틱이 섞이는 항목이라 숫자만 내고 판정은
사람이 읽고 한다.

걸린 자리는 문단 번호와 발췌로 나온다. 결과 보고엔 게이트 출력값을 그대로 쓴다.
인상으로 덮어쓰지 않는다. 그 글의 주제어는 `--protect "이 책,이 원고"`로 계수에서 뺀다.

## 테스트

```bash
python -m unittest discover -s tests -v
```

사람이 쓴 일기 세 문단은 exit 0, 전형적인 AI 글은 exit 1(대시·아니라·접속부사·블록리스트·
선언연쇄), 각주·숫자·따옴표 안 문장이 사라지면 exit 2, cp949 콘솔에서 생존. Ubuntu와 Windows
에서 CI가 돈다.
